# LAB-004 — Massive swarm: up to 1,000 real agents on micro-tasks, calibrated simulation to 100,000 (report)

> **Charts on this page, in order.** Real runs, N from 10 to 1,000 (log axis): baselines and the wound_resolution flag first (1 coverage, 2 false-success rate, 3 accepted tasks per US$, 4 duplicate calls per call), then the flags against the board base (5–8, same four metrics); then the per-flag comparison at N = 1,000 (9 accepted-per-US$ ratio, 10 false success, 11 coverage difference against the coverage-matched baseline). The calibrated simulation to 100,000 agents and its validation are on the companion card [LAB-004 — Calibrated simulation](/c/obs-lab004-simulation/). Raw runs, pool calibration and ledger are in `results/lab004/`.

Norevia Lab · 2026-11-09 · `PREREG.md` (+ Amendments 1–2) written before the main runs · **ledger US$ 9.86 counted of the US$ 15 cap** (counted = cost × 1.5; ≈ US$ 6.57 at the price table US$ 0.10/M in, US$ 0.50/M out, not an invoice; 82,545 calls, 312 of them failed pilot calls: output truncated at the token limit, or a rejected prefill request).

## Model route (matches the corrected briefing)
The briefing was corrected on 2026-11-09: **Claude Haiku 5.5 only** (the only model enabled on the key), no Luna, no OpenCode, with tiny contexts, prompt caching and the Message Batches API where latency allows. **Every real call used Claude Haiku 5.5 through the Anthropic API** (thinking disabled, ≈ 200 input and ≈ 100 output tokens per call, ≈ US$ 0.00008 per call). Before the correction I had made one test call each to GPT-6 Luna and a free open model; both were refused for usage limits (no tokens used, no spend) and neither appears in any result. **Real N = 1,000 was reached within the budget**, so no extension of the real range by simulation was needed (the simulation to 100,000 is the planned calibrated extension). **Prompt caching and the Batches API were not used:** prompts (≈ 200 tokens) are below the caching minimum, and agents act in sequential waves that need each result before the next wave, so batch latency would not fit; cost control came from tiny contexts and 4 calls per agent. Results are for Haiku 5.5.

## What was built (`norevia/observatory/lab004/`)
- **Environment + validator** (`tasks.mjs`, `node tasks.mjs validate`): 630 micro-tasks ("write one JavaScript function"), scored in a vm sandbox; 441 programming-by-example tasks (hidden 2-step function, 6–9 non-negative or mixed examples), 63 chained-step tasks, 126 prose-spec tasks; per task visible examples, 12 hidden tests, 8 probe inputs for behavioural signatures; 305 tasks have a validated trap (passes visible, fails hidden); 630/630 distinct, no constant solution passes. A task is **accepted** only if hidden tests pass; **false success** = committed on visible check but hidden fails.
- **Swarm engine** (`engine.mjs`): N agents, 4 rounds, waves with a board snapshot (race window), local visibility (30-task sample), 12 arms (3 baselines + ORCH-U + 7 flags + HISTORY control). The same code runs with the real backend (`backend.mjs`) or the simulated one (`sim.mjs`).
- Runner (`run.mjs`), pool calibration (`pool.mjs`), analysis (`analyze.mjs`), simulator (`sim.mjs`), curves (`curves.mjs`).

**Findings on scale.**
1. **Coverage saturates at N ≈ 300 at ≈ 0.41–0.48** (the pool is only ~45% solvable by this model with 4 attempts per agent): from 0.03 at N = 10 it rises steeply (≈ 0.7–1.0 log-units per decade up to N = 100, 0.5 to N = 300, 0.02–0.15 from 300 to 1,000), **smoothly with no jump** between neighbouring N (largest ratio between adjacent N is 3.5×, between 30 and 100, i.e. just the unsaturated slope).
2. **Beyond saturation, more agents only buy duplicates**: duplicate calls per call 0.14 (N=100) → 0.84 (N=1,000) for broadcast arms; accepted per US$ falls ≈ 5.5× from N = 100 to 1,000 for INDEP and BOARD for +0.0–0.2 coverage. Arms that stop duplicating keep their efficiency: ORCH (capped) and VOTE/LEADERS (fixed schedule) and, partly, WOUND (retires surplus agents: 2,764 calls instead of 4,000).
3. **Conflicts** (calls on tasks already committed) exist only without a board: INDEP 0.12 → 0.43 per call from N = 100 to 1,000; all board arms and ORCH have 0. **Messages per accepted task** at N = 1,000: ORCH-U 12, VOTE/LEADERS 7.5, WOUND 21, board arms 29–30, INDEP 0 (no coordination, no messages).
4. **Error correlation** (two wrong candidates for the same task share a behavioural signature): 0.38–0.55 for N ≥ 30, rising slightly with N (BOARD 0.31 → 0.43), no jump. This is why **majority voting hurts**: VOTE/LEADERS committed false successes in 46% (N = 300) and 60% (N = 1,000) of tasks against 22–25% for "commit on the first visible pass", because wrong answers agree (often on the same trap).
5. **No density transition.** LOCUST's gregarious share was 0.36–0.43 for N ≤ 300 and 0.19 at N = 1,000; it follows the failure-flip rule (about 60% of attempts fail), not density; the simulated share stays ≈ 0.40 from N = 10 to 100,000 at constant density. Vicsek/locust-style alignment did not show up in this setting.
6. **Throughput:** at N = 1,000 the critical path of a run is 7–97 s (slowest call per wave, 10 waves per round); accepted per minute of critical path: ORCH 1,300 (cap-limited, tiny run), ORCH-U 500, VOTE/LEADERS 405–433, board/INDEP arms 167–193, WOUND 258.

## Verdict per flag
Three readings are given, because the pre-registered reference turned out to be dominated by a modelling choice of mine (see Limits): **(P)** pre-registered rule, reference = best of {ORCH, INDEP, VOTE} by accepted per US$ (= capped ORCH at N ≥ 100); **(S)** post-hoc secondary, reference = best artificial baseline by coverage (INDEP at N = 1,000; ORCH-U at N = 300); **(B)** against the flag's own base arm. **Reading (P).** Every flag is WORSE under the pre-registered rule at N = 1,000, with Δcoverage +0.18 to +0.25 at ×0.13–0.38 the accepted/US$ of the capped orchestrator: the capped orchestrator makes 400 calls while the others make 4,000, so it wins efficiency by doing less, and covers 0.23 instead of 0.41–0.48. This is the registered verdict and stands; (S) and (B) are the informative ones. **Across (S) and (B), no flag beats a simple non-bio engineering control on coverage; the only flag with a clear, interval-backed advantage is `wound_resolution` (cost saving, equal coverage), and a plain "stop when resolved" dispatcher also gets it.** `informed_leaders` and voting trade 2× cost efficiency for 2.4× false success.

## Calibrated simulator
- **Fit** only on the pool calibration (630 tasks × 3 fresh attempts + 311 revise attempts: single-attempt hidden-pass 0.40, visible-pass 0.51, false-success share of visible passes 0.22, revise-after-failure hidden-pass 0.06) and real runs with N ≤ 100: per-task success and false-success profiles, wrong-answer agreement (ρ_wrong 0.42, ρ_false-success 0.96), revise gain, context effects, cost and latency per call.
- **Validation** on held-out real N = 300 and 1,000 for every arm (not used for fitting). **v1** (strong smoothing, α = 3) **failed**: coverage overpredicted by 36–56% at N = 1,000, only 3 of 12 arms passed (`sim-validation-v1.json`). **v2** (α chosen by cross-validation on the pool only, Amendment 2, after seeing v1 fail): **12 of 12 arms pass**; median coverage error 0–2%, maximum 10% (HISTORY at N = 1,000, 0.43 simulated vs 0.48 real); accepted/US$ error ≤ 8%; false-success rate errors up to 0.15 (HISTORY) and 0.09 (RENAL) (context effects on false success are not modelled). Caveats: the held-out runs use the **same 630 tasks** as the fit, so this validates swarm dynamics (selection, duplication, commit rules), not new tasks; v2's α = 0.05 means almost no smoothing of per-task estimates from 3 attempts; simulator success ignores agent identity and assumes independence given the task.
- **Extrapolation (simulation, exploratory, labelled; all 12 arms validated)**, `sim-extrapolation.json`: (a) fixed pool of 630 tasks: arms that retry unresolved tasks without limit (BOARD, INDEP, QUORUM, LOCUST, ECOLI, RENAL, HISTORY) keep gaining coverage slowly, 0.43 (N = 1,000) → 0.66–0.67 (N ≥ 30,000), but accepted per US$ collapses (900 → 14) and false success climbs from 0.25 to 0.33–0.34, because more attempts per task give a wrong-but-visible-passing candidate more chances to commit first; WOUND (0.42, accepted/US$ ≈ 1,200 at any N), ORCH-U (0.41–0.42) and VOTE/LEADERS (0.41, fs 0.59) plateau; (b) constant density (T = 2.1 N): coverage flat at ≈ 0.41–0.42 for BOARD/WOUND/RENAL/ORCH-U and ≈ 0.35–0.40 for INDEP/QUORUM/LOCUST, 0.26 for VOTE/LEADERS/ECOLI, accepted/US$ constant (≈ 3,000 for BOARD/WOUND/ORCH-U), **no phase transition** in coverage, false success, error correlation or gregarious share; the capped orchestrator collapses to 0.0007 coverage at N = 100,000 (central throughput bottleneck, by construction of the cap).

## Limits and incidents (all disclosed)
1. **Micro-task results do not transfer by themselves to real code work**: short single-function tasks with minimal context, visible/hidden tests, one cheap model; they say how coordination rules behave when work is tiny and verifiable, not how a swarm would do repository-scale engineering.
2. **Model:** Haiku 5.5, not Luna (blocked until 2026-11-11; free OpenCode blocked ≈ 21 h). Thinking disabled; the model "thinks aloud" in text for programming-by-example tasks unless told not to, which cost tokens and truncated 23% of calls in the first pilot (fixed before pre-registration).
3. **Environment tuning before the pre-registration:** the first task pool was at the ceiling (single-attempt 98–99%) with no false success; I added programming-by-example and chained-step tasks and tuned difficulty on 300-attempt pilots (disclosed in `PREREG.md`). The pool's ceiling (≈ 45% solvable in 4 attempts) is itself a property of these choices; saturation at N ≈ 300 is relative to this pool.
4. **Orchestrator cap (my modelling choice, 100 assignments per round)** drove the pre-registered reference; I noticed it after N ≤ 300 and added ORCH-U and a coverage-matched secondary verdict (Amendment 1, post-hoc). Both readings are reported.
5. **Simulator v2 was chosen after v1 failed validation** (Amendment 2); the held-out points were seen when v1 was judged, though not used to fit v2.
6. **Statistics:** one repetition at N = 1,000, two at N ≤ 300; intervals are across tasks of the same pool, not across independent worlds; task cost is attempts × mean cost per call; false-success and coverage differences at N ≥ 300 are small relative to wave-order randomness not captured by the task bootstrap. Flags are fixed-rule implementations, not model-chosen behaviours; `renal_compaction` was tested as context compaction of an agent's own recent solutions, which is one reading of the card.
7. **Wave and wall-clock:** wave = max(10, N/10) agents on one board snapshot (race window); wall time is not comparable across N because the API concurrency limit (150) throttles large runs, so only critical-path time is reported.
8. Cost: price table, not an invoice; counted ledger includes a 1.5 safety factor.
