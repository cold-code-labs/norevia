## Hypothesis (preregistered before the run)
Registered in `results/sims/PREREGISTRATION.jsonl` (2026-11-07T22:45:40Z, v1.0.0, code sha256 `1b704c3363684c5b…`).

Scaling multiplicatively while an error signal persists and contracting after resolution gives recovery comparable to a large fixed pool with idle cost close to that of a minimal pool; a persistence filter contains the cost of false alarms, and per-incident-type memory speeds up secondary responses.

- **P1** — Main scenario (false alarm f=0.01): clonal-g2-h1 is not dominated by any fixed N (1,2,4,8,16) in (idle cost, mean recovery) — for each fixed N, it is significantly better in at least one metric.
- **P2** — Clonal-g2-h1: idle cost ≤ 2× fixed-1 and recovery ≤ fixed-4.
- **P3** — Noisy scenario (f=0.05): persistence h=3 reduces idle cost by ≥ 30% vs h=1 with a recovery increase ≤ 20%.
- **P4** — Per-type memory reduces recovery (disjoint 95% CIs) with a total-cost increase ≤ 10%.
- **P5** — Slow contraction (c=0.8) increases idle cost vs c=0.5 without reducing recovery by more than 5%.

## Model
- 3000 steps; Poisson incidents (1 every 120 steps), 5 types with median work 20/40/80/120/200 agent-steps (lognormal, σ=0.5). Throughput with n agents = n^0.8 (coordination overhead), FIFO.
- Error signal: on if there is an incident open for ≥ 2 steps (detection delay) or a false alarm (prob. f per step).
- **Clonal:** if the signal has been on for ≥ h steps, n ← min(32, ⌈g·n⌉); if off, n ← max(1, ⌊c·n⌋). Memory: on detecting an already-seen type, jumps to the peak used last time.
- **Fixed:** N ∈ {1,2,4,8,16} always active.
- 1000 runs; same incidents for every policy and scenario (paired comparisons). Idle cost = Σ n(t) over steps with no open incident.

## Interpretation
- **Main result (P1 supported):** clonal is not dominated by any fixed pool. Against 16 fixed agents, it recovers slightly faster (11.8 vs 12.9 steps) with **5.6× lower** total cost (2.85 vs 16 agents/step) and ~13× less idle cost. This is the "expand under a persistent signal, return to rest" pattern working as promised **within the model**.
- **P2 not supported, because of a flaw in the metric:** fixed-1 has low idle cost because it is almost never idle — it is always behind (recovery 291 steps, 3.6 incidents open at the end). Idle cost is only comparable between policies with similar recovery; clonal pays ~1 agent-step per rest step (n_min=1) plus the contraction tail (32→1 in 5 steps).
- **P3 not supported:** with g=2, a 1-step false alarm costs only ~1 extra agent-step; the h=3 filter saved 7.8% of idle cost and delayed recovery by 15%. Persistence only pays off if false alarms are long or expansion is aggressive — the prediction overestimated the cost of false alarms.
- **P4 supported:** per-type memory (secondary response) reduces recovery by ~2.1 steps (−18%) at +3.1% total cost.
- **P5 supported:** slow contraction (c=0.8) increases idle cost by ~42% with no relevant recovery gain (−1.1%). Returning to rest quickly is cheap here because new incidents are rare.

## Limitations
- Independent incidents with divisible work (n^0.8); no incidents that worsen with intervention, no repairs that introduce faults, no activation/warm-up cost for agents (which would favour fixed pools).
- Perfect error signal after 2 steps (except 1-step false alarms); n_max=32 is reached in every run — clonal requires a peak capacity of 32 agents (reserve cost/concurrency limit not accounted for).
- **What needs validation with real LLMs:** cost of activating/deactivating agents (context, warm-up); whether the "error signal" (failing tests, alerts) is reliable enough to drive expansion; whether parallel repairs interfere with each other (real α); risk of cascade when a repair introduces new errors.
