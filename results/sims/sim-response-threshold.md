## Hypothesis (preregistered before the run)
Registered in `results/sims/PREREGISTRATION.jsonl` (2026-11-07T22:35:18Z, v1.0.0, code sha256 `27dcec91d1a39acb…`).

Heterogeneous response thresholds, reading only the local stimulus (backlog), allocate agents adaptively without messages: better latency than fixed roles sized for the mean, fewer active agents than fixed roles sized for the peak, and lower total cost than a central dispatcher when messages have a cost or when the dispatcher's information arrives late.

- **P1** — Threshold (θ~U[5,50], n=2, p_quit=0.1) has lower mean latency than fixed-mean (3+3), paired Δ with 95% CI < 0, with zero messages.
- **P2** — Threshold uses fewer active agents than fixed-peak (8+8) and has latency ≤ 2× that of fixed-peak.
- **P3** — A dispatcher with delay L=0 dominates the threshold rule when messages are free: fewer active agents **and** latency ≤ threshold.
- **P4** — The dispatcher's latency and peak backlog grow with L (0<2<5<10); for L ≥ 5 the dispatcher's peak exceeds the threshold rule's.
- **P5** — With a cost of 0.2 per message, the threshold rule's total cost/step < any dispatcher.

## Model
- 40 agents, 2 task types, 1000 steps, Poisson arrivals λ=1/type/step; 3 spikes of 50 steps with λ×4 (t=200 type A, 450 type B, 700 type A).
- An active agent completes 1 task of its type per step with prob. μ=0.5 if there is a queue. Cost = active agents per step (+ cost per message).
- **Threshold:** an inactive agent engages in type j with P = s_j²/(s_j²+θ_ij²), s_j = backlog of type j (read from the environment — no messages); an active agent quits with prob. p per step. Variants of θ and an engineering variant that quits when the queue is empty.
- **Fixed:** 3+3 (mean) or 8+8 (peak) always active.
- **Dispatcher:** observes queues and arrivals with delay L; target_j = ⌈(λ̂_j + queue_j/5)/μ⌉; messages = 1 status per active agent per step + 1 per (de)activation command.
- 1000 runs per strategy, identical arrivals across strategies (paired comparisons).

## Interpretation
- All five predictions were supported within the model.
- The threshold rule handles spikes without explicit communication: the backlog itself is the signal (stigmergic). The price is ~1.6 more active agents than the perfect dispatcher, because quitting is random (p=0.1) and does not know when the queue has emptied.
- The threshold rule has a **cost×latency knob**: low θ (2–20) → 16 active agents and latency 1.06; high θ (10–100) → 6.6 active agents and latency 2.4. Heterogeneity of θ barely mattered here (homogeneous θ=20 ≈ heterogeneous 5–50). The engineering variant "idle quit" (exploratory, no registered prediction) was **worse** in cost (9.70 active) with a marginal latency gain — the intuition of quitting when the queue empties did not help with these parameters.
- The dispatcher's advantage disappears with information delay: with L=10 the peak backlog is ~4× the threshold rule's and latency 58% higher, saving only ~0.7 active agents per step while spending ~9.7 messages/step.
- Fixed roles fail at both ends: sized for the mean, the backlog takes on average 232 steps to return to ≤ 5 after each spike (measurement cap 250); sized for the peak, it pays for 16 agents all the time.

## Limitations
- Homogeneous tasks with geometric duration; no specialisation (any agent serves any type with no switching cost).
- Simple dispatcher (proportional rule); better controllers may narrow the gap. The cost of "reading the backlog" was taken as zero for the threshold rule.
- **What needs validation with real LLMs:** real cost of messages/context for an orchestrator vs reading shared state; typical observation delay; whether LLM agents can apply a stable threshold rule without oscillating.
