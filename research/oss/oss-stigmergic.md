## Mechanism

1. **Communication topology.** It is a blackboard. No agent calls another: each "ant" reads and modifies rows of the `pheromones` table (`src/stigmergic/core/environment.py:L226-L248`), which live in SQLite with WAL (`environment.py:L524-L544`) or Postgres **[code]**. Selection is by `status` and an `entropy` threshold, ordered by `entropy DESC, id ASC` (`environment.py:L663-L701`) **[code]**. An event bus wakes consumers when the floor changes; `poll_interval` serves as a safety timeout (`src/stigmergic/agents/base_ant.py:L341-L354`; `environment.py:L287-L359`) **[code]**.
2. **Who decides who acts.** Nobody assigns tasks. The ant whose filter matches the task (`entropy_threshold`, `target_status`) takes it via an atomic `claim`, a `BEGIN IMMEDIATE` with SELECT+UPDATE (`environment.py:L703-L786`; `base_ant.py:L246-L255`) **[code]**. Concrete castes: Forager → `RAW`; Governance (`entropy>=0.7`, `RAW`) → `HYGIENIZED`; Solver (`HYGIENIZED`) → `PENDING_CONSENSUS`; Verifier (`PENDING_CONSENSUS`) → `RESOLVED`/`SLASHED` (`src/stigmergic/agents/concrete.py:L65-L103`, `L148-L197`, `L200-L236`; `src/stigmergic/agents/verifier_ant.py:L61-L111`) **[code]**. The default `SolverAnt` is a mock: it writes `"resolution": "Approved"` and the proposal `"Approved and executed the request: ..."` without an LLM (`concrete.py:L226-L236`) **[code]**. The "cloud" path of `HybridSolverAnt` is also simulated by default (`hybrid_ant.py:L176-L190`) **[code]**.
3. **Termination criterion.** Per task, there are terminal states `RESOLVED`, `SLASHED` and `DEAD_LETTER` (`environment.py:L116-L119`), excluded from `claim` (`environment.py:L733-L736`) **[code]**. By attempts: `max_retries=3`; `claim` increments `retry_count` (`environment.py:L763`) and, if `retry_count > max_retries`, the task goes to `DEAD_LETTER` (`base_ant.py:L222`, `L257-L272`) **[code]**. There is no global termination: each ant runs until `stop()` (`base_ant.py:L134-L149`, `L167-L179`). The examples stop by deadline or by `global_entropy() == 0` (`examples/01_hello_stigmergy.py:L156-L160`) **[example]**. The state machine (`environment.py:L128-L170`) is only enforced with `enforce_transitions=True`, off by default (`environment.py:L121-L127`, `L498`) **[code]**.
4. **Mechanical verification/acceptance.** `SemanticRaft.evaluate` is the gate. For each node `i` of the quorum, it applies the framing `perspectives[i % 3]` to the hypothesis (the proposal), asks the judge whether the premise (the original request) entails the hypothesis and approves if the label is `ENTAILMENT` with `score >= min_confidence` (default 0.0). It passes if `approvals >= approval_threshold` (`src/stigmergic/core/consensus.py:L503-L532`, defaults `quorum_size=3`, `approval_threshold=2`, `min_confidence=0.0` at `L411-L414`) **[code]**. A judge that throws an exception counts as a rejection (`consensus.py:L513-L517`) **[code]**. **By default**, a single `TransformersNLIJudge` (`cross-encoder/nli-deberta-v3-small`) is queried three times with different framings (`consensus.py:L72-L84`, `L441`), and the authors themselves comment "here a single model wears several hats" (`consensus.py:L75-L79`) **[code]**. The heterogeneous panel is optional (`judges=[...]`, `consensus.py:L387-L391`, `L422-L427`) **[code]**. Nature of the acceptance: it checks semantic entailment between request and proposal, **not** the correctness of the result against an oracle. The `RuleBasedJudge`/`MockNLIJudge` is deterministic, but it is a lexical heuristic (red flags + overlap of ≥1 token of 4+ letters, `consensus.py:L259-L301`). Therefore, it is not verifiable acceptance in the matrix's sense. Without proposal text, the judge receives a generic sentence "The request has been correctly handled..." (`consensus.py:L469-L472`) **[code]**.
5. **Technical cost/budget control.** None — not found (search: `budget`, `cost`, `token`, `max_iter`, `max_round`). The only limits enforced by code are `max_retries=3` per task (item 3), a 30 s `lease` (`environment.py:L496-L497`) and `max_tokens=512` for truncation by the local tokenizer in `HybridSolverAnt` (`hybrid_ant.py:L116`) **[code]**. The NLI pipeline cache avoids reloading the model, which is efficiency, not budget (`consensus.py:L172-L207`) **[code]**.
6. **Memory.** The floor is persistent and unbounded: there is no TTL, temporal decay or eviction (search: `decay`, `evaporat`, `ttl`, `prune`). "Evaporating" is only bringing `entropy` to 0 in a terminal state (`environment.py:L193-L194`; `consensus.py:L554-L569`), and the row remains. `reset()` deletes everything and is described as "primarily for tests/demos" (`environment.py:L1017-L1022`) **[code]**. The `SwarmInspector` telemetry uses a ring buffer of 10,000 events (`src/stigmergic/core/observability.py:L47`, `L58-L61`) **[code]**. Durable learning (`GardenerAnt._learn`) appears in the ServiceNow demo, after `PENDING_HUMAN` (`demos/servicenow_hr/ants.py:L385-L447`) **[example]**.
7. **Failures/retry.** An exception in `tick` is logged and swallowed, and the thread continues (`base_ant.py:L167-L179`). An exception in `metabolize` returns the task to `target_status` for a new attempt (`base_ant.py:L275-L287`, `L324-L339`). A stale concurrent write is rejected by version (CAS) (`base_ant.py:L294-L316`). Expired leases can be recovered by `reclaim_expired_leases` (`environment.py:L788-L835`) **[code]**. In the core nobody calls the reclaim; in the demo, a `JanitorAnt` does (`demos/servicenow_hr/ants.py:L223-L245`) **[example]**. If `metabolize` returns `None`, the task stays `CLAIMED` indefinitely until intervention or lease reclaim (`base_ant.py:L288-L292`) **[code]**.
8. **Communication pruning.** There is no removal of edges, messages or agents. `SLASHED` makes the proposal terminal and invisible to `claim`, which is task state and not channel pruning **[code]** (`environment.py:L116-L119`).
9. **Elastic vs fixed.** Fixed: the set of threads is instantiated by the user, and the core does not create or terminate ants on demand (search: `spawn`, `start(` in `src/`). "N identical ants" is possible because the claim is atomic (`base_ant.py:L203-L208`), but sizing is manual **[code]**.
10. **Cost vs quality benchmark.** There is no cost. There is an internal injection-capture benchmark (116 cases). In `RESULTS.md:L14-L19`, `single-judge`, `quorum-3` and `heterogeneous-panel` have **identical** numbers (82.1% capture and 50.0% FP) in torch-free mode **[README/docs]**. In torch-free mode, the "heterogeneous panel" combines `RuleBasedJudge` (an unmodified subclass of `MockNLIJudge`, `consensus.py:L304-L315`), another `MockNLIJudge` and an LLM stub that "mirrors the red-flag-plus-overlap heuristic" (`benchmarks/injection_capture/harness.py:L522-L538`, `L597-L612`, `L657-L667`) **[example]**. The "distinct model" test only compares names (`tests/test_consensus.py:L401-L403`) **[test]**. AgentDojo, InjecAgent and RAGAS appear as "planned" (`README.md:L261-L262`) **[README/docs]**.

## Evidence

- **Gaps:** there is no measurement of cost or of solution quality (the default Solver is a mock), and there is no external evaluation.
- No code was executed; no benchmark reproduced.

**Comparison with the previous study (A4 Master, rev. 2):**
- **Confirmed:** persistent trails (SQLite/Postgres); castes; proposal/review states (`PENDING_CONSENSUS`/`PENDING_HUMAN`, `environment.py:L71-L90`); SemanticRaft aggregates votes and decides by threshold; by default it queries the same model with different framings; a heterogeneous panel and test mocks exist; Apache-2.0 (now also read in `LICENSE`); the README acknowledges external benchmarks as "planned". The concern about correlated errors holds and is **reinforced**: in the committed benchmark, the quorum changes no number relative to a single judge, and the torch-free panel shares the same lexical basis (the stub itself admits this in `harness.py:L525-L529`).
- **Refinement:** the default judge is a small NLI cross-encoder, not a generative LLM; `LLMJudge` is optional (`consensus.py:L345-L375`). The trails do not decay over time: "evaporation" is zeroing `entropy` at the end of the life cycle.

## Engineering analogue

*(engineering hypothesis)* For the Swarm Efficiency Observatory, Stigmergic offers a **cheap and auditable coordination substrate** (atomic claim + DLQ + version) and a **jury acceptance gate** whose independence is the weak point. In the Observatory, SemanticRaft would be the "acceptance by correlated jury" condition, to be compared with "acceptance by executed test": measure cost per accepted task and the false-acceptance rate (proposal approved but failed by the test) across 1 judge, 3 framings of the same judge and 3 judges from distinct families.

## Testable hypothesis

1. *(hypothesis)* On tasks with an executable oracle, the false-acceptance rate of `SemanticRaft` with 3 framings of the same model does not differ from that of 1 judge (difference < 2 pp), while a panel of distinct families reduces it by ≥ 5 pp. Metric: false acceptances / accepted proposals, with Wilson CI; falsifiable if 3 framings reduce false acceptance as much as the heterogeneous panel.
2. *(hypothesis)* The cost per accepted task (judge calls + retries until DLQ) grows linearly with `quorum_size` with no gain in precision when the judges are correlated (vote correlation > 0.8). Metric: US$/accepted task × precision per configuration.
